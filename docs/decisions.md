# Решения (ADR)

## 1. processKey как уникальный ключ
**Статус:** принят  
**Причина:** нужен неизменяемый ключ для версий и ссылок из расчётов.  
**Следствие:** `processKey` задаётся на создание и уникален, `description` — только для отображения.

## 2. Версионирование процессов
**Статус:** принят  
**Причина:** расчёты должны ссылаться на конкретную версию процесса.  
**Следствие:** новое изменение — новая версия (v+1), а не перезапись.

## 3. Фильтрация через query‑params
**Статус:** принят  
**Причина:** стандартный REST‑подход для коллекций и проще расширять.  
**Следствие:** `GET /processes` поддерживает `type/page/size/sortBy/sortDir`.

## 4. Пагинация по умолчанию
**Статус:** принят  
**Причина:** безопаснее при росте данных, не перегружает API.  
**Следствие:** без параметров возвращается первая страница (`page=0`, `size=50`).

## 5. rateOptions вместо единого rate
**Статус:** принят  
**Причина:** для процесса есть фиксированные варианты скорости для типовых изделий.  
**Следствие:** процесс хранит список `rateOptions`, выбор варианта обязателен.

## 6. HandoffMode + batchVolume
**Статус:** принят  
**Причина:** нужно явно описывать возможность передачи результата частями.  
**Следствие:** `handoffMode = BATCHED` требует `batchVolume`, `FULL_ONLY` запрещает его.
