# Архитектура

## Общая идея
Проект следует принципам гексагональной архитектуры:
- Domain — чистая предметная область.
- Application — сценарии/сервисы.
- API — REST‑контроллеры и DTO.
- Infrastructure — MongoDB и мапперы.

## Модули (на текущем этапе)
- **Space** — справочник процессов и их версий.
- **Archive** — архив расчётов и выполнений (планируется).
- **Scheduler** — планирование выполнения (планируется).

## Space (текущий модуль)
### Границы ответственности
- Хранит процессы и их версии.
- Управляет справочником типов процессов.
- Проверяет валидность входных данных (уникальность, существование типа).
- Рассчитывает ожидаемое время по входным данным (без сохранения результата).
- Не управляет самим Order и не хранит расчёты.

### Версионирование процессов
- Любое изменение процесса создаёт новую версию (v+1).
- Клиенты должны ссылаться на конкретную версию процесса.
- Latest‑версии выдаются через отдельный запрос.

## Хранилище
- MongoDB используется как основное хранилище для MVP.
- Версии процессов хранятся как отдельные документы (processKey + version).
